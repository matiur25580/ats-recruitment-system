# HireFlow deployment: Render + Vercel + MongoDB Atlas

This repository is configured for the following production topology:

- **API:** Render Web Service, using the root `render.yaml` Blueprint.
- **Web app:** Vercel project rooted at `client/`, using `client/vercel.json` for React Router SPA deep links.
- **Database:** MongoDB Atlas, connected only from the Render backend.

## 1. Deploy the API to Render

1. Push the deployment branch to GitHub and connect the repository in Render.
2. Create a Blueprint from the repository root; Render reads `render.yaml` and creates `hireflow-api`.
3. Set the service's `MONGO_URI` to the Atlas SRV connection string, including the intended database name (for example, `hireflow`). URL-encode special characters in the database username/password.
4. Set `CORS_ORIGIN` to the exact Vercel production origin, without a trailing slash (for example, `https://your-project.vercel.app`). Add a comma-separated list only if multiple trusted frontend origins are intentionally used.
5. Set `CLIENT_URL` to the same frontend origin; password reset links use this value.
6. Add Cloudinary, Gemini and SMTP credentials in Render's Environment page. Keep every secret server-side; never add them to Vercel variables or source control.
7. Deploy and verify both `https://<render-service>.onrender.com/health` and `/ready`. The latter must report `database: connected`.

Render uses the platform-provided `PORT` and binds to `0.0.0.0`. The Blueprint sets one trusted proxy hop for Render's edge proxy; do not increase this unless the actual proxy topology is known.

## 2. Configure MongoDB Atlas

1. Create a dedicated production database user with the minimum database permissions required by HireFlow; do not use the Atlas project owner account.
2. Add the Render service's documented outbound IP address(es) to the Atlas IP access list. If the selected Render plan does not provide stable outbound IPs, choose a supported fixed-egress/private networking option before production. Do **not** leave `0.0.0.0/0` enabled for production as a shortcut.
3. Use the Atlas SRV connection string (`mongodb+srv://...`) and store it only as Render's `MONGO_URI` secret.
4. Confirm backups/restore policy and retention before storing real candidate resumes or personal data.

## 3. Deploy the frontend to Vercel

1. Import the same GitHub repository into Vercel.
2. Set **Root Directory** to `client`.
3. Framework preset: Vite. Build command: `npm run build`. Output directory: `dist`. Install command: `npm ci`.
4. Add the production environment variable `VITE_API_URL=https://<render-service>.onrender.com/api` (replace with the real Render API origin). Vite variables are embedded into the browser bundle at build time, so this value is an API URL, never a secret.
5. Deploy. `client/vercel.json` rewrites React Router paths to `index.html`, so refreshing `/login`, `/register`, `/dashboard`, and password reset routes does not return a Vercel 404.
6. Copy the final Vercel production origin into Render's `CORS_ORIGIN` and `CLIENT_URL`, then redeploy the API if changed.

## 4. Render environment variables

The Blueprint creates placeholders for these values:

| Variable | Required | Purpose |
|---|---|---|
| `MONGO_URI` | Yes | Atlas connection string |
| `JWT_SECRET` | Yes | Generated by Render; keep at least 32 characters |
| `CORS_ORIGIN` | Yes | Exact Vercel origin(s) |
| `CLIENT_URL` | Yes | Frontend origin for reset links |
| `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` | For resumes | Private PDF upload/download |
| `GEMINI_API_KEY` | For AI | Gemini resume analysis |
| `EMAIL_USER`, `EMAIL_PASS` | For email | SMTP account credentials |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `EMAIL_FROM` | Provider-dependent | Generic SMTP settings; omit host to use Gmail transport |
| `GEMINI_MODEL` | Optional | Defaults to `gemini-3.5-flash-lite` |

## 5. Production verification checklist

- [ ] Render deploy succeeds and `/ready` returns HTTP 200 with MongoDB connected.
- [ ] Vercel root and direct route refreshes return the app HTML.
- [ ] Browser API requests reach Render; CORS allows only the production Vercel origin.
- [ ] Register a real test candidate, log in, request password reset, and receive the email.
- [ ] Create a recruiter account through the approved/admin provisioning process; confirm recruiter job ownership.
- [ ] Upload a valid PDF, download it through the signed private URL, then delete it.
- [ ] Run the production integration smoke workflow with real provider credentials and inspect the test inbox/provider logs.
- [ ] Verify Atlas backup and perform a restore rehearsal before real users' data is stored.

Never paste secrets into chat or commit them. Enter them directly in Render's environment settings and GitHub's protected Actions environment.
